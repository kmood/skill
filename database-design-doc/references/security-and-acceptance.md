# 安全、运维与验收编制

按用户选定的安全等级与实际部署边界编制。涉及标准条款及符合性判断时核对现行官方标准，不把建议数值写成强制条款，不宣称设计文本即可证明通过测评。

## 安全控制

- 身份鉴别与授权：唯一身份、人工组合鉴别、服务账号凭据、账号生命周期、最小权限、单位部门或任务数据范围、职责分离及授权撤销。人工多因素入口与应用账号保护分别考虑，权限校验在服务端执行。
- 审计：覆盖登录、权限、结构变更、重要业务读写与解密等操作，记录主体、对象、时间、用途及结果，避免口令、令牌和人员明文进入日志。按实际需求设置独立留存及审计管理职责。
- 字段加密：范围由用户明确；仅人员信息加密时，不擅自扩展到全部业务字段、整库或备份介质。人员主表、同步表、快照及相关副本按内容统一盘点；字段名不足以确定是否含个人信息。
- 区分字段加密、传输密码保护、不可逆口令哈希与完整性认证。密文需足够存储长度、密钥与算法版本、随机量、认证保护，并绑定记录和字段上下文。产品和算法模式以确认的实现为准，不凭名称宣称合规。
- 手机号等低熵值确需等值查询时，考虑独立密钥、域区分的 HMAC 令牌，说明访问范围与规范化规则；普通无密钥哈希不作为充分保密措施。原唯一约束和查询行为须纳入迁移核验。
- 密钥与数据库权限分离，说明调用授权、轮换、独立保管及恢复依赖。新增密文列、检索列或附属表属于待实施迁移，不能改写源 SQL 基线造成“已经具备”的印象。
- 防篡改：主键、约束及事务保证业务一致性，恶意修改还需带密钥认证或签名、受控更新、版本校验和独立审计。普通摘要不能防止数据与摘要被一起重算；同库校验不足以覆盖整行删除和历史回退。按重要数据范围说明独立存证、删除事件、可信锚点、连续版本、可靠投递及核验失败处置。
- 备份与恢复：区分主备复制、可回溯备份及异地备份，说明扩展、权限、关联文件、密文与密钥的恢复依赖。RPO/RTO、备份频率及保留期使用批准值，建议值明确标注；异步复制不保证零丢失。
- 剩余信息与个人信息：覆盖缓存、导出、临时文件、历史备份及证明材料，说明保留和清理策略。重要数据保密要求超出现有范围时，指出需确认的差异及设计变更，不擅自增加用户排除的方案。

## 运维及验收

按项目内容选择连接、长事务、阻塞、慢查询、磁盘、归档、复制、备份和分区覆盖监控；阈值按资源及业务目标确定。变更记录版本、依赖、迁移、回滚和验证；不把带 DROP TABLE 的导出文件作为生产直接执行方案。

验收清单由解析结果动态生成，核对实际表字段、约束、显式索引、分区边界、扩展和字典数据，不固化本次项目统计数字。验证关键业务链路、孤立引用、级联删除、NO ACTION、可空唯一约束、权限撤销、解密和检索、防篡改、备份恢复；脚本未声明的关系说明维护责任。检验结果和配置证据支持结论，未实施项保留为要求或待办。
